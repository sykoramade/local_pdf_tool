## Design Context

### Users
Technically literate professionals who handle sensitive documents: healthcare workers,
HR teams, researchers, journalists, legal/ops staff. They've been burned by scammy
PDF tools (iLovePDF clones, mybestpdf) that bait-and-switch on downloads or quietly
upload files to servers. They are skeptical. They open DevTools. They read privacy
policies. The job: process a PDF quickly, privately, without creating a compliance
problem. The emotional need: confidence that their documents are safe.

Secondary audience: students and researchers who annotate papers and don't want
unpublished work on a stranger's server.

### Brand Personality
**Trustworthy · Precise · Calm**

The tool earns trust by showing proof, not asserting promises. Copy is direct and
unhurried — it doesn't need to shout because the architecture does the talking.
The brand sits closer to a professional instrument (a good text editor, a legal
form, a well-made utility knife) than a consumer app. No delight for its own sake.
Delight comes from things working exactly as expected.

Brand name is **TBD** — do not reference a specific product name in design decisions.
Current codebase uses "PDFNoLimit" but this is under review. Use neutral references
("the tool", "the app") in copy suggestions.

### Aesthetic Direction
**Light with dark accents.** Light gray (`gray-50`) base preserved for the main
content areas. The hero and primary sections use the current light treatment but
with stronger typographic authority. A **dark navy feature bar / footer band**
(`#0c111d` or equivalent) anchors the page and signals professional seriousness
without requiring a full dark-mode redesign.

Reference aesthetics: Vercel (technical authority), Stripe (clean trust), a
well-designed law firm site (unhurried, precise). **Not**: startup-blue gradients,
glassmorphism, rainbow accents, shield/padlock animations, confetti, excessive
rounded corners.

**Type:** Currently Tailwind default (system Inter stack). Aspiration: introduce a
display serif (DM Serif Display or similar) for hero headings only — editorial
weight, not decorative. Body stays clean sans-serif.

**Color:**
- Base: `white` / `gray-50` — clean, not clinical
- Primary accent: `indigo-600` (existing, keep for interactive elements)
- Dark band: `#0c111d` (near-black navy, not pure black)
- Trust green: `#059669` / `emerald-600` for confirmation states and trust badges
- Destructive: `red-600` for errors only

**Theme:** Light mode only for now. Dark mode is backlog.

### Design Principles

1. **Proof over promise.** Any trust claim must be accompanied by verifiable evidence
   (DevTools screenshot, open source link, network tab result). Marketing assertions
   without proof are forbidden. When in doubt, show the mechanism, don't describe it.

2. **Professional restraint.** Every decoration must earn its place. If removing an
   element doesn't hurt comprehension or trust, remove it. Whitespace is intentional,
   not accidental. Animations serve orientation, not entertainment.

3. **Feature hierarchy matches user intent.** The most common action is always the
   most prominent element. Trust signals come *before* feature lists — users need
   to believe the tool is safe before they care what it can do.

4. **Consistency as trust signal.** Visual inconsistency between tool pages (editor,
   compress, merge, sign, split) erodes confidence. The compress page is the
   established reference pattern. New pages inherit it. Deviations require a
   documented reason.

5. **Copy earns the click; features justify the upgrade.** Landing page hierarchy:
   privacy claim → proof element → CTA → features → pricing. Never lead with
   features. The free tier must feel genuinely free — no dark patterns.

### Current Codebase Patterns (as of Sprint 8)
- Reference component: `app/app/compress/page.tsx` — all new tool pages inherit this structure
- Container: `max-w-2xl mx-auto px-4 py-16`
- Heading block: `text-center mb-10`
- H1: `text-3xl font-bold text-gray-900 mb-3`
- Subtitle: `text-gray-600`
- Badge row: `mt-8 flex flex-wrap justify-center gap-5 text-sm text-gray-500`
- Trust badge check: `<span className="text-green-500">✓</span>`
- Cross-links: `mt-12 text-center` with `text-indigo-600 hover:text-indigo-800 text-sm font-medium underline`
- NavBar: shared `components/NavBar.tsx` — all pages use it

### Known Design Debt (as of Sprint 8)
- Editor idle state: `text-4xl` h1 (vs `text-3xl` on all other pages) — intentional or bug TBD
- Sign page: heading block top padding too low, badge row has workaround `px-4`
- No cross-links on sign page idle state
- No DevTools proof element anywhere yet
- No audience-specific landing pages yet

### Anti-patterns (explicit DO NOT)
- No padlock animations or shield badge icons
- No gradient hero backgrounds (solid color only)
- No glassmorphism or frosted backgrounds
- No Inter as a display/hero font (it's fine for body)
- No raw usage counters in the UI (gate on features, not counts)
- No modal-on-entry patterns
- No "AI slop" card grids with icons that could describe any product
- No dark patterns on pricing (no hidden limits, no bait CTA)
